# Plan optimizacije performansi — korak po korak

Redoslijed je **(ubrzanje × učestalost interakcije) ÷ trud**. Koraci 1 i 4 su brzi dobici
koji se mogu uraditi odmah; koraci 2, 3 i 5 rješavaju najgore prijavljene simptome
(resize, density, tipkanje, reordering); koraci 7–9 su arhitekturalni i rade se postepeno.
Svaki korak je samostalan i može se mergati kao zaseban PR.

## Sažetak problema (dijagnoza)

Glavni uzrok tromosti je **monolitna state arhitektura**: svih ~27 `useState`-ova plus
TanStack-ov interni state žive u korijenu (`useMRT_TableInstance`), pa svaka interakcija
(pomak miša tokom resize-a, hover pri drag-u, density, tipkanje filtera, paginacija)
re-renderuje kompletno stablo tabele. Memoizacija nizvodno je gotovo nemoguća jer je
`table` instanca referencijalno stabilna ali **mutabilna** — propovi se "nikad ne mijenjaju",
pa bi obični `React.memo` zamrznuo UI (zato postoje custom komparatori u `memoMode`,
koji je po defaultu isključen). Trajno rješenje je selector/atomic sloj stanja (korak 7),
a do tada lokalni fixevi ispod.

## KORAK 2 — Resize kolone: 0 rendera tokom drag-a, 1 render na commit, bez remounta

**Trud: srednji (≈1 dan). Dobitak: najveći pojedinačni — trenutno svaki piksel pomaka
renderuje toolbar + sve head ćelije + footer, a start i kraj resize-a rade PUNI REMOUNT
body-ja (restart animacija u ćelijama).**

### Zašto se animacije u ćelijama restartuju (skriveni bug)

U `src/components/table/MRT_Table.tsx` (linije 79–83) tokom resize-a se **mijenja tip
komponente**:

```tsx
{memoMode === 'table-body' || columnSizingInfo.isResizingColumn ? (
  <Memo_MRT_TableBody {...commonTableGroupProps} />
) : (
  <MRT_TableBody {...commonTableGroupProps} />
)}
```

`Memo_MRT_TableBody` je za React **drugi element type** od `MRT_TableBody`. Na startu
resize-a React unmounta postojeći body i mounta novi; na kraju resize-a swap ide nazad —
**dva puna remounta po gesti**. CSS/GIF/Lottie animacije kreću ispočetka jer DOM čvorovi
nastaju iznova. Cilj ovog koraka: React tokom drag-a **uopšte ne učestvuje**.

### 2.1 Ukloni swap tipa komponente

`src/components/table/MRT_Table.tsx` (linija 79): izbaci `|| columnSizingInfo.isResizingColumn`
iz uslova — ostavi samo `memoMode === 'table-body'`. Body je uvijek isti tip komponente,
remount nestaje zauvijek. Zamrzavanje više nije ni potrebno jer poslije 2.2 tokom drag-a
nema nijednog rendera koji bi trebalo blokirati.

### 2.2 Resize handler bez ijednog upisa u React state tokom geste

Priprema — ref na `table` element:

- `src/hooks/useMRT_TableInstance.ts` (linije 74–86): dodaj
  `const tableRef = useRef<HTMLTableElement>(null);` i
  `const isResizingRef = useRef<false | string>(false);` pa ih ubaci u `table.refs` (linija ~401).
- `src/components/table/MRT_Table.tsx`: proslijedi `ref={tableRef}` na MUI `Table` komponentu.

Zatim u `src/components/head/MRT_TableHeadCellResizeHandle.tsx` (linija ~29) zamijeni
`header.getResizeHandler()` vlastitim handlerom:

- **mousedown/touchstart:** NIŠTA ne piše u state. Zapamti `startX` i `startSize`,
  postavi `isResizingRef.current = column.id`, direktno kroz ref postavi
  `data-mrt-resizing` atribut na container i `cursor: col-resize` + `user-select: none`
  na `document.body`. Upali indikator iz 2.3.
- **mousemove/touchmove:** piše samo CSS varijable direktno na `table` element:

```ts
const size = Math.min(
  Math.max(startSize + dir * (x - startX), column.columnDef.minSize ?? 40),
  column.columnDef.maxSize ?? 1000,
);
tableEl.style.setProperty(`--header-${parseCSSVarId(header.id)}-size`, `${size}`);
tableEl.style.setProperty(`--col-${parseCSSVarId(column.id)}-size`, `${size}`);
// + pomjeri indikator: indicatorEl.style.transform = `translateX(${px}px)`
```

  Ćelije već čitaju širinu iz tih varijabli (`src/utils/style.utils.ts`, linije 99–106),
  pa kolona prati kursor bez React-a. `dir` je `-1` za RTL (`columnResizeDirection`).
- **mouseup/touchend:** skini listenere, resetuj ref/atribute/kursor, sakrij indikator,
  pa JEDAN poziv:

```ts
table.setColumnSizing((old) => ({ ...old, [column.id]: size }));
```

  Commit, persist i kontrolisani `onColumnSizingChange` konzumenti dobiju vrijednost.
  Taj render izračuna `columnSizeVars` na iste vrijednosti koje su već u DOM-u —
  **nema vizuelnog skoka**.

`columnSizingInfo` se tokom drag-a **uopšte ne postavlja** (ni na startu). Double-click
reset (linije 43–49 u ResizeHandle) ostaje kakav jeste — jedan render je tamo u redu.

### 2.3 Vizuelni indikator kao jedan DOM element, ne kao stilovi ćelija

`draggingBorders` u head/body ćelijama (`MRT_TableBodyCell.tsx` 114–168,
`MRT_TableHeadCell.tsx` 107–133) danas crta resize liniju kroz React stilove — to bi
zahtijevalo render. Zamijeni resize-granu tih stilova jednim apsolutno pozicioniranim
elementom u `src/components/table/MRT_TableContainer.tsx` (container već ima
`position: relative`):

```tsx
<Box
  ref={resizeIndicatorRef}
  sx={{
    position: 'absolute', top: 0, bottom: 0, width: '2px',
    bgcolor: 'primary.main', display: 'none', zIndex: 3,
    pointerEvents: 'none',
  }}
/>
```

Handler mu na mousedown upali `display: block` i na svaki mousemove postavlja
`transform: translateX(...)`, na mouseup ga sakrije — čista DOM manipulacija kroz ref
(isti pristup kao AG Grid). Vizuelno bolje: linija ide punom visinom tabele bez obzira
na virtualizaciju. Ref proslijedi kroz `table.refs` (npr. `resizeIndicatorRef`).

### 2.4 Ugasi hover/tooltip efekte tokom drag-a kroz CSS, ne kroz state

`handleColumnCellHoverToggle` u `MRT_TableHeadCell.tsx` (linije 163–167) čita
`columnSizingInfo.isResizingColumn` da suzbije hover tokom resize-a — pošto ga više ne
postavljamo, zamijeni čitanjem `table.refs.isResizingRef.current`. Globalno, na container
(postavljen u 2.2):

```css
[data-mrt-resizing] { user-select: none; }
[data-mrt-resizing] .Mui-TableHeadCell-Content-Actions { visibility: hidden; }
```

Hover ikonice, tooltipi i selekcija teksta miruju tokom drag-a bez ijednog rendera.

### 2.5 Počisti preostala čitanja `columnSizingInfo`

- z-index grana `column.getIsResizing()` u `style.utils.ts` (linija ~187) — više se ne
  aktivira tokom drag-a; ostavi je (bezopasna) ili prebaci z-index na indikator iz 2.3.
- `transform` za `columnResizeMode: 'onEnd'` u `MRT_TableHeadCellResizeHandle.tsx`
  (linije 52–59) — s novim handlerom razlika 'onChange'/'onEnd' praktično nestaje
  (oba su "live prati kursor, commit na kraju"); granu ukloni ili zadrži samo kao
  API kompatibilnost.

### Rezultat koraka 2

| Događaj | Sada | Poslije |
|---|---|---|
| Start resize-a | Full render + **remount cijelog body-ja** | 0 rendera |
| Svaki mousemove | Full-tree render (toolbar, head, footer) | 0 rendera (2 CSS varijable + translateX) |
| Kraj resize-a | Full render + **drugi remount body-ja** | 1 render (commit `columnSizing`) |
| Animacije u ćelijama | Restartuju se 2× po gesti | Netaknute |

Commit-render na mouseup je **re-render, ne remount** — React pomiri iste DOM čvorove,
CSS animacije se ne resetuju. Iznimka: JS-vođene animacije koje se same restartuju pri
ponovnom izvršavanju komponente (npr. Lottie bez guard-a) — njih umotaj u `React.memo`
sa stabilnim propovima ili uključi `memoMode: 'cells'`.

**Edge slučajevi za pokriti:** RTL smjer (predznak delte), touch eventi, clamp na
`minSize`/`maxSize`, scroll tokom drag-a uz virtualizaciju kolona (novi cell-ovi čitaju
iste CSS varijable — konzistentno), `Escape` za otkazivanje (bonus), kontrolisani
`state.columnSizing` konzument.

**Provjera:** Profiler tokom povlačenja ručke 2–3 sekunde — smije postojati **samo 1
commit** (na mouseup), kolona vizuelno prati kursor, animirane ikonice u ćelijama se ne
restartuju ni na startu ni na kraju.
**Rizik:** srednji — provjeri RTL, min/max, double-click reset i touch.

## KORAK 5 — Hover/drag stanje van korijena (popravlja reordering kolona/redova)

**Trud: srednji-velik (≈1 dan). Dobitak: drag preko N ćelija prestaje raditi N full-tree rendera.**

### 5a. Novi fajl `src/utils/mrtStore.ts`

```ts
export const createSliceStore = <T>(initial: T) => {
  let value = initial;
  const listeners = new Set<() => void>();
  return {
    get: () => value,
    set: (next: T | ((v: T) => T)) => {
      value = next instanceof Function ? next(value) : next;
      listeners.forEach((l) => l());
    },
    subscribe: (l: () => void) => {
      listeners.add(l);
      return () => listeners.delete(l);
    },
  };
};
```

### 5b. `src/hooks/useMRT_TableInstance.ts` (linije 175–180)

Zamijeni 4 `useState`-a (`hoveredColumn`, `hoveredRow`, `draggingColumn`, `draggingRow`)
store-ovima kreiranim u `useRef`-u (jednom po instanci). **Izbaci ih** iz
`definedTableOptions.state` objekta (linije 227–228, 234–235) i okači na instancu
(`table._hoverStore`, `table._dragStore`). Setteri `table.setHoveredColumn` i ostali
(linije 431–445) sada zovu `store.set` — javni API ostaje isti.

### 5c. Novi hook `src/hooks/useMRT_SliceValue.ts`

```ts
import { useSyncExternalStore } from 'react';

export const useSliceValue = <T, R>(
  store: { subscribe: (l: () => void) => () => void; get: () => T },
  selector: (v: T) => R,
): R => useSyncExternalStore(store.subscribe, () => selector(store.get()));
```

### 5d. Ažuriraj potrošače na boolean selektore

- `MRT_TableBodyCell.tsx` (71–84): `const isHoveredColumn = useSliceValue(table._hoverStore, (s) => s.hoveredColumn?.id === column.id);`
  itd. — `draggingBorders` memo (114–168) sada zavisi od 4 boolean-a, ne od objekata.
- `MRT_TableHeadCell.tsx` (60–67) isto.
- `MRT_TableBodyRow.tsx` (86–87): `isDraggingRow` / `isHoveredRow`.
- `style.utils.ts` (177–181): `opacity` u `getCommonMRTCellStyles` — primi booleane kao
  parametre umjesto poziva `getState()`.
- Grab handle-ovi i `MRT_ToolbarDropZone` (čita `hoveredColumn?.id === 'drop-zone'`).

**Provjera:** povuci kolonu preko 5 kolona uz Profiler — re-renderuju se samo ćelije te
dvije kolone, ne toolbar i ne svi redovi.
**Rizik:** srednji — `grep -rn "hoveredColumn\|draggingRow\|hoveredRow\|draggingColumn" src/`
i pokrij SVAKO čitanje; `getState()` neka vraća snapshot iz store-a radi kompatibilnosti.

## Napomena o React Compileru (2026)

Ne uvoditi prije koraka 5/7 — uslovni hookovi (vidi korak 9) ga blokiraju, a mutabilna
`table` instanca (interior mutability preko `getState()` na stabilnoj referenci) mu je
nesiguran teren. Compiler NE rješava: context value identitet (korak 9), identitete
propova preko granice paketa (korak 8c), ni root-level state kaskadu (korak 7). Kad store
sloj bude gotov, compiler može zamijeniti većinu ručnih `useMemo`/`useCallback` iz
koraka 6 i 8.
